# Соответствие проекта ЛР‑2

## Структура HTTP-методов

Через ORM работают пять обработчиков:

1. `GET /chronicles/feed` — одна опубликованная летопись из БД.
2. `GET /chronicles/add` — черновик текущего пользователя или первый шаг добавления.
3. `GET /chronicles/catalog` — плитка и серверный фильтр по `start_year`.
4. `POST /chronicles` — создание черновика после кнопки «Далее».
5. `POST /chronicles/{chronicle_id}/publish` — заполнение и публикация черновика.

Шестой обработчик `POST /chronicles/{chronicle_id}/delete` выполняет логическое удаление через SQL `UPDATE` и курсор `psycopg2`.

## Что исправлено по замечаниям

- В начальной БД ровно семь опубликованных карточек, один черновик и одна удалённая запись.
- Убрана кнопка «Предыдущий». Кнопка «Следующий» после последней записи открывает первую.
- Добавление разделено на два этапа: название и медиа → «Далее»; описание и два поля → «Опубликовать».
- Фото и видео при добавлении не отправляются на сервер. В черновик записываются недоступные URL, поэтому HTML показывает два локальных файла по умолчанию.
- В каталоге есть серверный числовой фильтр по году начала; введённое значение сохраняется.
- Удалённые записи отсутствуют в ленте и плитке и недоступны по ID.
- Лайки только отображаются и считаются по таблице `likes`; постановки лайка нет.
- Все обычные кнопки используют класс `action-button`. Элементы ленты справа считаются иконками.
- Названия кода, URL и полей БД приведены к единому английскому `snake_case`; русский используется в интерфейсе и значениях статусов.
- В проекте оставлены только `media/chronicle_default.jpg` и `media/chronicle_default.mp4`.
- Дизайн основан на мобильной ленте Pinterest. Цвета: `#800020`, `#F4EFEA`, `#231F20`.

## Подготовка БД

`database/init.sql` пересоздаёт три таблицы и заполняет демонстрационные данные. При существующем Docker volume автоматический init повторно не запускается; файл следует выполнить в Adminer вручную. Перед этим нужно сохранить нужные данные, поскольку скрипт удаляет старые таблицы.
